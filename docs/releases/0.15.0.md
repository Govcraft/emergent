# Emergent 0.15.0

Quiet sources stay connected to the engine. In 0.14.0, a publish-only source
that sent no IPC frame for 60 seconds was disconnected. HTTP sources could
continue accepting requests while their events never reached the engine.

The engine now disables idle-read timeouts for connections without
subscriptions. It retains a separate, bounded policy-admission timeout through
acton-reactive 10.0.0. Existing primitive binaries benefit when the engine is
upgraded; rebuilding a primitive is not required for the idle-timeout fix.

The Rust SDK also rejects new fire-and-forget publishes once it knows the
connection is closed. A publish racing a disconnect can still be queued before
the failure is observed. Queue success is not delivery confirmation; use
`publish_ack()` when the caller needs the engine's response. This release does
not add automatic reconnection or replay.

## Upgrading

The engine and SDKs are versioned 0.15.0. Update Rust applications to
`emergent-client = "0.15"` and rebuild to receive the SDK's disconnect handling.
The IPC wire format is unchanged, so older primitives still communicate with
the upgraded engine.

The Rust SDK now depends on acton-reactive 10.0.0. Its public
`From<acton_reactive::ipc::IpcError>` conversion targets acton 10's error type.
Applications directly using acton 9 error values must upgrade that dependency
or map the error explicitly. This public type change is why the release is
0.15.0 rather than 0.14.1.

## IPC timeout configuration

Emergent overrides `read_timeout_ms` to zero for its long-lived primitives.
`admission_timeout_ms` and `subscription_read_timeout_ms` retain the values
loaded from acton's IPC config, or their defaults of 60,000 and zero milliseconds.

```toml
# ~/.config/acton/emergent/ipc.toml
[timeouts]
admission_timeout_ms = 60000
subscription_read_timeout_ms = 0
```

In acton 9, `read_timeout_ms` also controlled admission. If you customized it for
an admission deadline, transfer that value to `admission_timeout_ms` explicitly.
Setting the new admission value to zero disables that deadline as well.
